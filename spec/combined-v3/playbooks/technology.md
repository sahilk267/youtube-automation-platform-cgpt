# Technology OS — TEST-BEFORE-CLAIM CHAIN

1. Collect official docs, release notes, version, pricing/usage rights, published benchmark claims and security advisories with retrieval date.
2. Extract falsifiable assertions; separate vendor-claimed feature, locally observed behavior, third-party reported result and future marketing promise.
3. Build reproducible isolated test environment, pinned dependencies, input fixtures, command logs, exact hardware/OS and repeated runs. If access/device/API unavailable, label `NOT_TESTED`—never invent benchmark.
4. Normalize metrics by comparable workload, latency/throughput, hardware, model version and total cost. Security claims require advisories or controlled tests, not generic judgement.
5. Show original screen recording, interactive steps and verified tutorial; replace sensitive tokens and user data with synthetic examples.
6. Run version drift watcher; when documentation or pricing changes, create update task and invalidate time-sensitive comparisons.
7. Outputs: versioned product matrix, test logs, screenshots with provenance, safe tutorial plan and limitations; evaluation by reproducibility.

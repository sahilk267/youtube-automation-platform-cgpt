# CORE-15 — TYPED LOCAL API, AUTHORITY BOUNDARIES AND COMPATIBILITY

1. Every listed operation from `contracts/openapi.yaml` must have typed request and response; where old OpenAPI says `{type: object}` the implementing agent must first file an explicit proposal/migration that references `ExecutionRequest`, `ExecutionResult` or a **named** contract, and add positive/negative contract tests. Incomplete API schema is **not permission to infer arbitrary keys**. `GET /health` is public only to localhost (and must reveal no secrets).
2. Standard API envelope `{request_id, contract_version, data, pagination?}` for success and `{request_id, contract_version, error:{code, safe_message, retryable, trace_id}}` for failure. Typed data depends on endpoint schema. `Idempotency-Key` mandatory for mutating job/remote actions; same key+same payload returns same durable job; key+different payload -> conflict. `If-Match` required to edit current project/channel revision.
3. Local-only auth mode: bind 127.0.0.1, use CSRF token on mutation and session authentication where browser access exposes state-changing endpoints. No unrestricted CORS. If remote host/UI is enabled, require explicit operator setup and a threat review; never silently expose to LAN.
4. Record HTTP request trace IDs and error codes, but never OAuth tokens, cookies, full private transcripts or personal data in logs. Use OS-specific secret store or encrypted local store with externally protected key (no fixed key checked into repo).
5. Keep contract version 2.0.0 for v2.1; existing workspaces remain readable. Schema changes require additive migration, compatibility fixtures and an ADR. Unknown fields rejected in contracts with `additionalProperties=false`.
6. Pagination must be stable, bounded and deterministic; list endpoints require `limit`, `cursor`, `sort` enumerations and response `next_cursor`. UTC timestamp serialization is RFC 3339; user time zone affects presentation only, with DST gap/duplicate tests for US sports scheduling.
7. Failure codes: `INVALID_CONTRACT`, `UNAUTHORIZED`, `FORBIDDEN`, `IDEMPOTENCY_CONFLICT`, `STALE_REVISION`, `SPEC_CONFLICT`, `FEATURE_NOT_ENABLED`, `REQUIRES_SOURCE_PERMISSION`, `SOURCE_STALE`, `RIGHTS_UNRESOLVED`, `REVIEW_REQUIRED`, `GPU_UNAVAILABLE`, `QUOTA_EXHAUSTED`, `REMOTE_STATE_UNKNOWN`. Every code needs user-facing recovery.
8. Source URLs or model strings must never be interpolated unescaped into FFmpeg command lines, shell scripts, SQL, regex or HTML. Use args-array subprocess APIs, parameterized SQL, safe JSON serialization and UI escaping.

**Outstanding contract-closure requirement:** Existing v2 OpenAPI documents route intent but many concrete body types are unresolved. Agents must implement typed endpoint-specific request/response specs and pass API conformance before claiming a service released. This is an explicitly tracked implementation deliverable, not something proven by this document.
